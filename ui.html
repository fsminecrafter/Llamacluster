Optional tools — extra capabilities; permissions still apply
Semi lets the model search, read and edit workspace files and run safe commands (ls, cat, grep, find, mkdir, cp, mv…) inside the workspace on its own, and asks before deleting files, running anything else, or touching paths outside the workspace. Uncontrolled lets it run any command as you.
Tool output longer than this is cut off (≈4 characters per token) before it is sent back to the model, so big file reads or web pages can't overflow the context window. Software mode and Orchestra workers use at most 1000. Default 3000.

Terminal
A real shell on the controller computer, sandboxed to the workspace: it sees only the workspace (as /workspace), runs as a normal user (no root, no sudo), has read-only system tools and no network unless the controller was started with --term-net. Needs bubblewrap (sudo apt install bubblewrap). Closed after 30 minutes without use.

🎯 Recommend model

Looks at the memory and estimated speed of every online node, searches Hugging Face for GGUF models, and picks the most capable one that should generate at your target speed and still fit in memory. Speeds are estimates (memory bandwidth ÷ model size); “capability” is a heuristic (parameters, MoE active size, quantisation loss, age), not a benchmark. Models split into several .gguf files are skipped.

Looks for the most capable model that fits in the combined memory of the head node's GPU(s) and the helpers' memory, and estimates the speed including network delay. The model file is only needed on the head node.
Find the best finetune of a model
Enter a Hugging Face repo, link or plain name. Finetunes that have a GGUF are checked against the same memory and speed limits above, then ranked by community adoption (downloads and likes) — Hugging Face has no objective quality score, so read the model cards.

⚡ Maximise cluster

Chooses one model for the cluster and the best settings for every node (GPU layers, threads, slots, context), keeps the per-request context the same on every node, and sets load-balancing weights so faster nodes receive proportionally more requests. Figures are estimates from hardware + GGUF headers; check the logs after applying.
